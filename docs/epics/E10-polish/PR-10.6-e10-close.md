### What this PR writes

**`docs/epics/E10-polish/RETRO.md`**, and the shape is fixed:

1. **What §18 said E10 was, and what it turned out to be** — the same opening E7 and E8
   use. Five of six rows already merged; the sixth was an audit; the two decisions §18
   asked somebody to make (skeletons, the online-only default) and what they were.
2. **The screen inventory. This table *is* the retro.** Every route in
   `routes.guest.jsx`, `routes.student.jsx`, `routes.teacher.jsx` and `routes.admin.jsx`,
   at 375px, in four states:

   | Route | Shell | Loading | Error | Empty | Populated |
   |---|---|---|---|---|---|
   | `/` | guest | — | — | — | ✅ |

   ✅ / ❌ / ⏳ and **never a blank cell**. A `—` is allowed only where the state cannot
   exist and the row says why — `/` makes no request, so it has no loading state, and that
   is a fact about the screen rather than a gap in the pass.
3. **Findings**, numbered `F1…`, each with what was observed, why it happens, and where the
   fix goes. E8's four findings are the model: a finding names the two correct decisions
   that met, not just the symptom.
4. **The mutation ledger**, in E7's format — every row written by hand and every column
   hand-set, with the undo written **before** it was run. E10 is a rendering pass and the
   honest expectation is that this table is short or empty; if it is empty, say so in a
   sentence rather than omitting the section, because "this pass wrote nothing to the
   database" is itself the result.
5. **What the pass did not cover.** First line of it: **§14.4's 768–1024 and >1024 rows
   were not audited.** Then the routes that came back ⏳ and why, and the duplicated
   `connected` boolean 10.4 left in `useSessionState.js`.
6. **Open items**, as a table with a destination for each — the same shape as E8's.
7. **What one epic of polish cost, in plain words.**

**`docs/README.md`** — the E10 row in the epic index. It says what is true, including the
word "provisionally" and the open count if that is what is true. Three PRs are already
queued on that table (6.9, 6a.6, 6b.4); different rows, and whoever lands second rebases.

**`docs/OWNERSHIP.md`** — §2 gains a row for anything E10 created and nothing else:
`client/src/components/system/ConnectionBanner.jsx` and `client/src/hooks/useSocketConnected.js`
(10.4), and `client/tests/` (10.2), which is the first test directory outside `server/`
and needs an owner named before somebody adds a second one with a different idiom.

### What this PR must carry forward rather than fix

- **E8's F1–F4 are still open** and E10 did not touch them. The retro says so rather than
  letting a reader assume a polish epic swept them up.
- **E8's F5 is still open** — `server/.env` carries production Neon credentials and shadows
  the root `.env` for anything run from `server/`. E10 ran nothing from that directory,
  which is the safest relationship to it and not a fix.
- **`6b.4` is open and the deployed offer path is still broken.** Nothing in E10's docs may
  claim the deployed product works. The pass ran against `localhost:5173` and the retro says
  which host.

## Review checklist additions

- **The inventory is evidence, not a summary.** A ✅ means somebody looked at that route in
  that state at that width. If a row was reasoned about rather than observed, it is ⏳.
- **Findings name the collision, not the symptom.** "The retry button is below the fold" is
  a symptom; "`ErrorState`'s `minHeight` is 200px and the screen it sits in is 800px tall,
  so a correct component and a correct call site produce an unreachable control" is a
  finding.
- **No fix in this diff.** Including the two-line ones. Especially the two-line ones.

## Notes

E8's close read from a production Neon database before noticing, because a script was run
from `server/`. This pass has no script and no database step — which is the point of the
inventory being a browser walk. If a step in this close seems to need `psql`, it has drifted
into being a different epic's pass.

The handoff's last line is the standard this document is held to: *write down what you find,
including the parts that fail. E7's and E8's retros are useful documents because their most
valuable lines are the ❌ ones.*
