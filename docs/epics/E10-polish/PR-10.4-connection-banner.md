## Scope

**The socket is visible on exactly one screen and the case the row was written for is on a
different one.**

`hooks/useSessionState.js` tracks `connected`, re-joins the room on reconnect and re-reads
the session; `SessionRoom.jsx` renders a five-word marker beside the timer. That is 6.8's
work and it is correct. Everywhere else in the product, a dead socket is silent.

The case this row exists for: a teacher on `/teach`, `status: 'ONLINE'`, availability toggle
green, socket down. They receive no `offer:new`. They are told nothing. From their side the
platform has no students tonight — while the server's atomic lock hands an offer to them and
it expires unanswered against `OFFER_TTL_SECONDS`, costing a real student sixty seconds and
a place in the ranking they were matched into.

### What this PR builds, and it is one component

`client/src/components/system/ConnectionBanner.jsx`, mounted once in `AppLayout`, as the
first child of `AppShell.Main`, above the boundary 10.3 put around the `Outlet`.

`client/src/hooks/useSocketConnected.js` is the state behind it: subscribe to the singleton's
`connect` and `disconnect`, seed from `socket.connected`, unsubscribe on unmount. Nine lines.

The freeze governs the rest and is not restated here except for the two rules a reviewer
will reach for first: **no retry button** — Socket.IO's backoff is already retrying, and a
button that races it can only make the reconnect slower or the user's belief about it wrong
— and **not on the guest or auth shells**, because `lib/socket.js` connects on
`status === 'authenticated'` and on nothing else, so a banner there warns about a connection
the visitor never had.

Three details the freeze leaves to this PR:

- **A grace period before it appears.** A reconnect that resolves in 300ms must not flash a
  warning; a banner that appears and vanishes teaches the user to ignore banners. The
  component waits `DISCONNECT_GRACE_MS` before rendering and disappears the instant the
  socket is back. The constant lives in the component, the way `HEARTBEAT_MS` lives in
  `lib/socket.js` — `MVP.md`'s no-magic-numbers rule points at
  `server/src/config/constants/`, and a render timing is not a business rule.
- **It occupies layout space and does not stick.** A fixed overlay at 375px eats a quarter
  of the viewport on the one device this epic is about. The cost is that a user scrolled to
  the bottom of a long screen cannot see it; that is recorded in 10.6's retro as a known
  limitation rather than solved with `position: fixed`.
- **One sentence, role-neutral, and it names the consequence rather than the cause.**
  "Reconnecting — you may not see new offers or session updates until this clears" is what a
  person can act on. "WebSocket disconnected" is not.

### What this PR does not build

- **No reconnect logic.** §18's row says "banner + auto-reconnect" and the reconnect exists
  twice already: Socket.IO's own backoff, and 5.7's `TOKEN_EXPIRED` refresh-then-reconnect
  path in `lib/socket.js`. A third would be two implementations fighting over one socket.
- **No change to `useSessionState.js`.** It keeps its own `connected` flag. Extracting it to
  use the new hook would be the right refactor and it opens E6's file to change how the
  session screen learns about its socket, mid-epic, for tidiness. The duplication is one
  boolean, it is named here, and 10.6's retro carries it as an open item.
- **`SessionRoom`'s inline marker stays**, per the freeze. Both files get a comment naming
  the other so the next reader finds the reason before the duplication.

## Acceptance criteria

- [ ] With the server stopped, every authenticated route — `/app`, `/app/wallet`, `/app/history`, `/teach`, `/teach/earnings`, `/teach/profile`, `/admin/sessions` — shows the banner
- [ ] Restarting the server makes it disappear on its own, with no reload and no button
- [ ] `/`, `/teachers`, `/pricing`, `/login`, `/register` **never** show it, logged in or out
- [ ] A disconnect shorter than `DISCONNECT_GRACE_MS` produces no banner at all
- [ ] The banner is in the document flow: content below it moves down, and nothing is covered. At 375px `scrollWidth === clientWidth` with the banner up
- [ ] On `/app/session/:id` both the banner and 6.8's inline "Reconnecting…" marker appear, and read as one situation rather than two
- [ ] Logging out with the banner up removes it along with the shell; logging back in does not leave a stale one
- [ ] No new socket is opened — `lib/socket.js`'s singleton is the only connection. Check the network tab: one `/socket.io` upgrade, not two
- [ ] `npm test` passes at the count 10.2 left it at; `npx eslint client/src server/src` is clean

## Manual test

1. `npm run dev` — or use the pair already running on 3000 and 5173.
2. Log in as `dana.k@demo.tutornow.il` / `TutorNow!2026`. Sit on `/teach` at 375px.
3. Stop the server. Within a few seconds the banner appears; the availability toggle is still green, which is exactly the situation it is warning about.
4. Start the server. The banner disappears by itself.
5. Log out. Open `/pricing` — no banner, server up or down.
6. Log in as a student, open a session screen, stop the server: banner at the top, "Reconnecting…" beside the timer, and the countdown keeps counting — which is 6.8's point and still true.

## Review checklist additions

- **`lib/socket.js` is not in the diff.** A banner that needed to change the socket would be
  a banner that is doing more than reporting.
- **`useSessionState.js` is not in the diff.** The duplicated boolean is deliberate and
  named; removing it is a refactor of E6's session hook and it needs its own PR.
- **No `position: fixed`, no `position: sticky`.** Freeze §2, and the reason is 375px.
- **No retry button, no dismiss button, no auto-close.** Three separate ways this component
  could turn into a toast.
- **The banner renders from a hook, not from `getSocket().connected` read during render.** A
  socket property read in a render body is not reactive and will be right exactly once.

## Notes

`lib/socket.js`'s header is worth reading before this PR: it explains why the connection is
module state driven by the auth store rather than by a component, and the banner is the
first thing in the product that observes that lifecycle without participating in it. The
hook must only add and remove listeners — the same rule `useSocketEvent` was built under.

The teacher-goes-quiet case has a server-side counterpart that already works and is not
what this PR is about: `sockets/handlers.presence.js` and the auto-away sweep decide when a
teacher stops being matchable. This banner is about the ten minutes before that, when the
platform still believes the teacher is there and the teacher still believes the platform is.
