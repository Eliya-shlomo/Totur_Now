## Scope

**This is the audit, and the audit is the epic.** Not a hunt for broken layouts — that
hunt was already run, at 375×812, before the briefs were split, and fourteen of the
twenty-four routes came back clean with no element's right edge past 375px. **What has
never been looked at is the other three states.** Every one of those measurements was
taken on a populated screen with a healthy server.

So: twenty-four routes × four states — **loading, error, empty, populated** — at 375px,
each recorded as ✅ / ❌ / ⏳ and **never blank**. The recording is 10.6's; the walking and
the fixing are this PR's.

with the reason — E6a exists because that classifier has been down for an entire
verification pass before, and a ⏳ with a reason is worth more than a ✅ nobody earned.

### How the error state is forced, because guessing is not measuring

Stopping the server is not available — another session's `node --watch` is serving both
ports and the handoff says leave it alone. Breaking the server is worse. So the failure is
injected in the page, which is also closer to what a phone on a bad train actually does:

```js
// In the browser console, before navigating to the route under test.
const send = XMLHttpRequest.prototype.send;
XMLHttpRequest.prototype.send = function (...args) {
  this.addEventListener('loadstart', () => this.abort());
  return send.apply(this, args);
};
// Undo: reload the page. Nothing is patched on disk.
```

Axios uses `XMLHttpRequest` in the browser, `api/client.js`'s interceptor turns the abort
into an `ApiError` with a readable message, and every screen's error path starts from
there. **The empty state is forced with data, not with a patch** — a fresh student has an
empty wallet and an empty history, and Dana K. has no earnings today.

### What gets fixed here, and what does not

**A fix that needs a file not on the allowlist is a finding, not a fix.** That rule is the
whole defence against this PR arriving as a four-thousand-line diff nobody can review, and
it is the rule CONVENTIONS states from the other side: never reformat a file you are not
otherwise changing.

Concretely:

- Every change is listed in the PR description with the route and state that produced it.
- **`TeacherCard.jsx` may be changed only with all four of its screens re-measured in the
  same commit** — `/teachers`, `/app/ask/:id/teachers` through `MatchCard`,
  `/app/session/:id` in `OFFER_SENT` through `AwaitingResponse`, and `/teach/profile`.
  §14.2 calls the second of those the screen that decides whether the product works.
- **Nothing in E8's four open findings is touched.** `MatchCard` renders the numbers F1 is
  about; the ordering is not fixed here.
- No `Skeleton` is added — that was ruled in the freeze and 10.2 encoded it.

### The one breakpoint literal in the client

`components/question/ImagePicker.jsx:40`:

```js
const CAMERA_BREAKPOINT = '(max-width: 48em)';
```

`48em` is `theme.breakpoints.sm`. This is the precise failure the freeze on `theme.js`
exists to prevent, it has been there since E3, and it survived four epics because nobody
was reading breakpoints as a set. It becomes
``useMediaQuery(`(max-width: ${theme.breakpoints.sm})`)`` off `useMantineTheme()`, which is
the idiom `AppLayout` already uses.

**And then it is enforced.** `client/tests/state.contract.test.js` — 10.2's file — gains a
fourth assertion: no file under `client/src` outside `theme.js` contains a literal
`36em`/`48em`/`64em`/`75em`/`88em`, `375px`, `768px` or `1024px` **in code**. Prose in a
comment is allowed and there are eight of those today; the assertion strips comments before
it looks. It lands in this PR rather than in 10.2 because 10.2 could not have made it pass.

## Acceptance criteria

- [ ] All twenty-four routes visited at 375×812, each in all four states, each recorded — ✅, ❌ or ⏳ with a reason. **No cell is blank**
- [ ] `document.documentElement.scrollWidth === clientWidth` on every route in every state, including with the connection banner up
- [ ] No element's `getBoundingClientRect().right` exceeds 376 on any of them
- [ ] Every state reached is legible: no truncated single-line control, no button under 44px of touch target, no text at the default size inside a 40px-wide column
- [ ] The error state was **forced and observed** on every route that makes a request — not inferred from the code
- [ ] `grep -rn "48em\|768px\|1024px\|375px" client/src --include=*.jsx --include=*.js` returns only comments and `theme.js`
- [ ] The fourth assertion is in `client/tests/state.contract.test.js` and re-introducing `CAMERA_BREAKPOINT` makes the suite red
- [ ] `npm test` passes at 10.2's count **+1**; `npx eslint client/src server/src` is clean
- [ ] Every changed file appears in the PR description with the route and state that justified it
- [ ] `git diff --stat` contains no file from the denylist

## Review checklist additions

- **Every diff hunk traces to a row of the inventory.** A change nobody can point at a route
  and a state for is polish nobody asked for, and this is the epic where that becomes four
  thousand lines.
- **No Prettier run over anything.** `docs/` is in `.prettierignore` and the client is not.
  If a file's diff is mostly re-wrapping, it was formatted rather than fixed.
- **`theme.js` is not in the diff.** If a value seems to need a home there, the component is
  the home; if it needs two homes, it needs one component.
- **A ❌ is a result.** The pass records what it could not fix, and 10.6 carries it into the
  retro. E7's and E8's retros are useful documents because their most valuable lines are the
  ❌ ones.

## Notes

The negative result from the pre-brief sweep is worth keeping in mind while walking this:
`AppLayout` has driven §14.4's `< 768px` branch since PR 0.5, `SimpleGrid cols={{ base: 1, … }}`
is already the idiom in every grid, and both modals are already full-screen sheets below
`sm`. **The expected outcome of this pass is mostly ✅**, and the value is in the four or
five cells that are not — which are far more likely to be a loading state that is 200px tall
in front of an 800px screen, or an error state whose retry button is below the fold, than a
layout that overflows.

§14.4's other two rows — 768–1024 and >1024 — are **not** audited. The epic README says so
in its deviations table and 10.6's retro says it again as the first thing the pass did not
cover. One width, honestly, beats three widths claimed.
