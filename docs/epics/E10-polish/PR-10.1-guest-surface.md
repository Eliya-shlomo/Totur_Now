## Scope

to prevent.

### The online-only ruling

`MVP.md` §18's row 10.2 says **"Public online-teachers list"**. The list is not online-only:
`findTeacherPage`'s `onlineOnly` defaults to `false`, `teacherListSchema` defaults the query
parameter to the string `'false'`, and `TeacherFilters` renders it as an unchecked switch.

**The default stays `false`, and this PR is where that is written down.**

- A guest opening `/teachers` at 23:40 with an online-only default sees an empty list, and
  learns nothing about the product. The page's own header — "It is the surface that has to
  convince somebody to register" — is the argument: a visitor is browsing what the platform
  *has*, not dispatching a question right now. Dispatching is `/app/ask`, which is behind a
  login and is a different screen with a different algorithm (§9.1's hard filters, where
  `ONLINE` is mandatory and always has been).
- **Every seeded teacher is `OFFLINE`.** An online-only default would render the demo
  database as an empty product, which is also what an audience sees in E11.
- Online-ness is not hidden by this choice. `TeacherCard` has rendered a live `OnlineDot`
  since 2.5 and `isOnline` is on the contract; a guest can see who is available without the
  list deciding for them.
- **Changing the default is a server change** — `teacher.public.schema.js` and
  `teacher.repository.js` — and E10 has no server work. If a later epic disagrees, that is
  its PR with its own acceptance criteria, not a widened brief here.

What §18's row actually wants is that the online list be **reachable**, and today it is
reachable only by finding a switch three controls into a filter bar. So:

**The landing page gets a second call to action that links to `/teachers?onlineOnly=true`.**
One link, in `GuestCta`, beside the existing primary. The filter already lives in the URL —
2.5 made that decision so a filtered list is a link somebody can send — so this needs no new
state and no new parameter.

**And the path that link creates gets an honest dead end.** With one click now landing a
visitor on a filtered-empty list at midnight, `Teachers.jsx`'s empty state must offer
**"Show all teachers"** for the online-only case rather than the generic "Clear filters":
clearing is right when a level and a band are also set, and wrong when the only filter is
the one the landing page just applied. The message says so in one sentence — teachers go
online when they are free, and the rest of the list is still worth reading.

**Nothing else on these four screens changes in this PR.** Anything else the guest surface
turns out to need is 10.5's, where it is one row of a pass rather than an unbounded polish
budget.

## Acceptance criteria

- [ ] `/` at 375px shows two calls to action, both reachable without horizontal scroll, and the second lands on `/teachers?onlineOnly=true`
- [ ] That URL loads with the online-only switch **already on** — the filter reads from the query string, so this is a check that nothing was reimplemented in state
- [ ] With every seeded teacher `OFFLINE`, that URL shows an empty state whose action is **"Show all teachers"**, and pressing it lands on `/teachers` with a populated grid
- [ ] With a level or band also set, the empty state still says "Clear filters" — the generic branch is unchanged
- [ ] `/teachers` with no query string is **unfiltered** and shows offline teachers. The default did not move
- [ ] `document.documentElement.scrollWidth === clientWidth` on `/`, `/teachers`, `/teachers?onlineOnly=true`
- [ ] `npm test` passes at 886; `npx eslint client/src server/src` is clean
- [ ] `git diff --stat` touches three files and no more

## Manual test

## Review checklist additions

- **The default did not move.** `grep -n "onlineOnly" server/src` must return the same five lines it returns on `main`. A server file in this diff is a failed review.
- **`TeacherCard.jsx` is not in the diff.** It is rendered by `/teachers`, by §14.2's selection screen through `MatchCard`, by `AwaitingResponse` and by `/teach/profile`. A change made while looking at the guest list is a change to the screen `MVP.md` says decides whether the product works.
- **The empty-state branch is a branch, not a rewrite.** The existing `hasFilters` logic and its message stay; the online-only case is an additional case.

## Notes

E2's retro recorded the filters working — "22 → 11 (`level=5`) → 5 (`+band=B`) → 3
(`+onlineOnly`), and the URL restores the controls" — so the mechanism this PR leans on is
measured rather than assumed.

§12's row for this screen is `GET /public/teachers/:id`, and E2 already ruled that a teacher
list is not `/public`: `/public` is taxonomy and money, cached for `PUBLIC_CACHE_SECONDS`,
and a teacher who just went online would be served stale for the rest of the day. That
ruling is why the online-only switch can be trusted to be live at all, and it is the reason
this PR does not need to think about caching.
