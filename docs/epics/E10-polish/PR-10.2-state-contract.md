## Contract implemented

The epic README's contract freeze §1, turned from a paragraph into an assertion.

`MVP.md` §18's row **10.5**, and `CONVENTIONS.md` → Client: *"Every list has an empty
state. Every async view has a loading state and an error state. This is a review item, not
a polish item."*

## Scope

**The contract is already met almost everywhere, and this PR is mostly about making that
survive the next twenty screens.** Measured on `main` at `78554ca`:

- Fifteen page files import from `@/api/`. Fourteen render both `LoadingState` and
  `ErrorState`; the fifteenth is `RateSession.jsx`, which posts and never reads.
- Every single `ErrorState` call site in the client passes `onRetry`. Nineteen of nineteen.
- Seven files render `EmptyState`, and every list that can come back empty is one of them.

So there is no rescue work here. There are three specific defects, one decision to encode,
and one gap in how any of it is enforced.

### There are no skeletons and none are added

§18's row says "loading skeletons". The epic README's contract freeze §1 carries the full
argument and it is not repeated here; the summary is that a skeleton is a second copy of a
layout, every list in this product has a variable-height row, and the one thing a skeleton
buys over a spinner — no layout shift — is what `LoadingState`'s `minHeight` prop already
buys without the copy.

**What is actually wrong is the call sites, not the component.** Three of them take the
200px default while standing in for content that is much taller or much shorter, so the
page jumps when the data lands:

| Call site | Stands in for | Today |
|---|---|---|
| `components/wallet/LedgerList.jsx:51` | a paged transaction list on `/app/wallet` | no `minHeight` |
| `pages/student/Dashboard.jsx:116` | the balance card | no `minHeight` |
| `pages/teacher/Dashboard.jsx:202` | the standing block | no `minHeight` |

Each gets a `minHeight` measured against its own populated height at 375px — measured, not
guessed, and the number is recorded in the PR description. **This is the whole of the
skeleton work and it is three props.**

### The contract has never been enforced by anything but review

Nothing fails if screen twenty renders `<Center><Loader /></Center>` and calls it a loading
state. CONVENTIONS says it is a review item; a review item that a machine can check should
be checked by the machine, and this epic is the one that noticed.

**This PR adds `client/tests/state.contract.test.js`** — source-reading assertions, the
idiom `wallet.service.test.js` and `wallet.topup.test.js` already use on the server side:

1. **Every file in `client/src/pages/` that imports from `@/api/` renders `LoadingState`
   and `ErrorState`.** Exemptions are a named list in the test with a reason beside each,
   not a loosened regex. There is exactly one today — `RateSession.jsx`, which posts a
   review and reads nothing.
2. **`Loader` is imported by `components/state/LoadingState.jsx` and by nothing else that
   uses it as a view state.** One named exception: `components/question/ImagePicker.jsx`
   renders a `Loader` *inside* a control, over an image thumbnail while the upload runs.
   That is a busy indicator on a button, not the loading half of an async view, and the
   test says so where the exception is listed.
3. **Every `ErrorState` call site passes `onRetry`.** Nineteen of nineteen today, and the
   assertion is what keeps the twentieth honest.

**This is a deliberate widening and it is named rather than smuggled.** The client has had
no test directory since PR 0.1, and adding one means one line in the root `package.json`'s
`test` script — a shared file under `OWNERSHIP.md` §4. It is one line, it adds no
dependency, it touches no lockfile, and the alternative — filing a test about client source
under `server/tests/` because that is where the glob happens to point — is the kind of
thing this repository writes retros about. The count that `npm test` prints goes up and the
commit message says by how much, per the handoff's §3.2.

**No screen's rendering changes in this PR except the three `minHeight` props.** If the
test finds a fourth violation the fix is a line in the exemption list *with a reason*, or a
follow-up PR — not a relaxed assertion. "The suite went red and I updated the expected
value" is how a rule becomes a bug, and E8's brief for 8.2 is where that sentence comes
from.

## Review checklist additions

- **The three components in `components/state/` are not in the diff.** The finding is that
  the call sites are wrong, not that the components are.
- **The `minHeight` numbers are measured.** Each one is the populated height of the thing it
  replaces at 375px, read off the browser, and the PR description says what was measured.
  A round number that nobody measured is a guess with a decimal point.
- **The exemption lists are lists, not regexes.** An assertion that excludes
  `pages/**/Rate*.jsx` excludes a file nobody has written yet.
- **One line in `package.json`, and no lockfile.** If `package-lock.json` is in the diff,
  something installed a dependency and this PR does not need one.

## Notes

The reason this PR exists as its own thing rather than as a bullet inside the mobile pass is
E8's ordering argument, applied to a smaller case: 10.5 measures twenty-four routes in four
states, and a measurement taken while the loading states are still changing attributes
whatever it sees to whichever change is easier to notice.

`ProtectedRoute.jsx:30` renders `<LoadingState label="Checking your session…" minHeight="60vh" />`
and is the one call site that already got this right — a string `minHeight` rather than a
number, because the thing it stands in for is a whole screen. It is worth reading before
picking the three numbers.

## What the first run found — amended after the fact

The retry assertion went red immediately, on a call site the grep audit that preceded this
brief had missed: `pages/student/Ask.jsx` renders an `ErrorState` with `minHeight={0}` and
no `onRetry`, under the question form.

**It is correct code following an unstated rule**, and the rule is now stated where the
exemption lives: an `ErrorState` that stands *in place of* the content needs a retry,
because it is the only control on screen; one rendered *beside* content that already
carries the action does not, and a second button there would be two controls for one
decision. 3.6 wrote it that way on purpose — its own comment says everything typed is still
on screen — and `minHeight={0}` is the same statement in layout.

So the exemption lists carry three entries rather than two, and the third is the argument
for the file existing: a grep found what it was told to look for, and the assertion found
the case nobody had thought to describe.
